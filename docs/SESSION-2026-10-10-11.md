# fastcontrol Session, October 10–11, 2026

## Scope And Naming

The relay now controls Codex and Claude Code sessions through one Android app. The product and Android display name are `fastcontrol`. A project directory can still contain a hyphen, and its name remains visible under the chat title. The subtitle shows project, branch and computer. The provider logo inside the context ring identifies the agent.

The repository and release downloads remain private. Installer scripts live in this repository. A GitHub authorization header is required when downloading them with curl or PowerShell. README commands use an existing GitHub CLI login. No public bootstrap was published.

## Provider And Host Support

Codex reads the desktop state database and rollout files, then uses the desktop IPC router for live control. The private protocol is compared with the installed desktop bundle. Claude Code reads native JSONL sessions and runs the installed CLI with bidirectional streaming, approvals, questions and interrupts. Provider caches, notification identities and launch intents remain separate. Opening the app returns to the last-used provider's recent chats. The header dropdown switches providers.

Claude live verification in this work used Haiku 5.5 with Low effort. Follow-ups queue into distinct turns. Stop clears the queue and interrupts the active turn. Archive preserves native transcripts. An externally managed session opens for viewing, with explicit Take Over before starting a managed process. Saved model aliases do not replace the actual model reported by a transcript.

Mac release builds target Apple Silicon only. The bundled speech runtime requires macOS 13.3. Native Windows support targets Windows 11 ARM64, with a named-pipe IPC client, process-tree termination, native CLI discovery, Windows URI opening, and a pure Go SQLite driver. A separate ARM64 workflow runs Windows tests and builds the Windows relay and speech runtime. Live control against an authenticated Windows desktop still requires a Windows machine. The existing Mac installation uses its original SQLite CLI and Unix socket.

## Voice Recording And Transcription

Android records 16 kHz mono AAC at 32 kbps when the selected relay advertises AAC. Older relays and Windows hosts without FFmpeg receive PCM WAV. Capability negotiation keeps existing clients compatible. A recording goes over the network to the computer selected for the chat, which transcribes it locally and returns an editable draft. The app does not send that draft to the coding agent automatically.

MacWhisper discovery prefers an installed Parakeet v3 model. Without a supported installed model, the installer prepares the bundled whisper.cpp runtime and multilingual Whisper Base Q5 model, approximately 57 MiB. Windows uses the bundled whisper.cpp runtime. Its optional FFmpeg decoder enables AAC; WAV works without that dependency.

A measured compressed recording uploaded 19.6 KB rather than 143.3 KB of decoded PCM, an 86% reduction. It returned the expected draft in 550 ms, including 417 ms of server transcription. These measurements describe one short LAN test. The user also reported accurate longer recordings and network activity generally below 100 KB/s after compression.

The Mac converts AAC with CoreAudio. The decoder has a deadline and watches decoded output size. The relay canonicalizes WAV headers and enforces mono 16 kHz PCM and a two-minute limit. Temporary recordings, decoded audio and transcript output files are removed. A bounded inference slot rejects concurrent transcription requests rather than allowing memory growth.

## Optional Model Setup

The installer asks whether to prepare speech. `--skip-speech`, `-SkipSpeech` on Windows, or `FASTCONTROL_SKIP_SPEECH=1` skips the model download. Tapping the microphone on a host without a model opens a setup prompt. The install button starts a download on that selected host, with progress and a preparation stage in Android. Closing the prompt does not stop the installation.

Authenticated `/speech/install` GET and POST requests report or start one installation. A mutex protects the installation claim, progress and configuration. A private download is checked for size and SHA-256, warmed with silence, then published. A local race diagnostic with 24 simultaneous POSTs observed one download. The runtime is bundled, so end users do not need a paid speech app, Python or Homebrew.

## Chat Controls And Motion

The composer row is Attach, Permissions, Model, Intelligence, Voice, Stop and Send. The microphone sits immediately left of Stop. Model text stays readable, with a small dropdown arrow. The intelligence gauge is larger and brighter. Stop is a true circle, and the idle microphone is white. Recording adds a subtle microphone halo.

The Listening strip is a compact horizontal row above the message field. It retains the waveform, duration and Cancel action without hiding the model, effort or input. Tapping the microphone again stops recording and transcribes. There is no separate Transcribe button. Preparing and Transcribing disable the microphone, and transcription includes a spinner.

The larger context ring contains the OpenAI or Claude mark. Tapping it opens context and activity details, including elapsed time. The timer does not occupy the chat header continuously.

New outgoing messages, responses, commands and logical transcript lines enter with a fast 180 ms slide and a one-pixel overshoot. History opens immediately. Existing DOM nodes stay in place during incremental rendering, so animation and decoded images survive updates. Text catches up within 220 ms and new text fades briefly. Reduced-motion settings avoid movement.

A persistent Thinking strip sits above the composer throughout an active turn, including steering and gaps between tool updates. Its text has a continuous moving highlight. Blocking approvals or questions show their request card instead. Nonblocking questions can remain visible while the agent continues thinking. The indicator stops when the turn finishes.

## Questions And Images

Question cards use a small Your Input header, readable Markdown prompt, separate option title and description, a Recommended label where supplied, a typed-answer field and Send Answer. Multiple asynchronous questions render together and submit a combined answer. Selecting an option does not send it immediately. Unchanged card updates retain a typed answer.

Images appear inline for uploads, generated results and tool reads. Opening an image uses a full-screen viewer with zoom, pan and native downloading. Relay images are fetched with authentication and shown as blobs inside Android.

A prior flicker briefly collapsed images to placeholders during transcript updates. A phone recording exposed it around 14.6 to 15.2 seconds. The renderer now reuses decoded image buttons. The later animation implementation also avoids replacing unchanged children, because reparenting an animated node cancelled its motion. Native verification retained ten image nodes and the same turn height across 40 forced updates.

Repeated `cua_repl.js` tool rows are hidden. Their image results remain visible. Successful Send and Steer actions do not show a Sent toast.

## Release And Verification

Releases v0.1.0 through v0.1.4 established the provider relay, image viewer, optional speech setup and compressed uploads. Version 0.1.5 adds compact voice controls, provider marks, transcript motion, persistent progress and question formatting. Android keeps the same signing key and package ID so upgrades retain pairing and app data.

Focused verification includes Go vet and tests, Mac race checks, Windows ARM64 cross-compilation, native Windows pipe/SQLite/voice contracts in CI, inspection of packaged executables, signed Android builds, installed-phone geometry and animation checks, and isolated question interactions. Live Claude generation tests must remain Haiku 5.5 at Low effort.

Windows packaging includes project dependencies' licences and a statically linked whisper.cpp build. Its installer verifies hashes, checks executable startup, installs an interactive per-user login task and preserves tokens and model data. The Windows workflow artifact is published only after its build checks pass.

Machine addresses, pairing tokens, raw transcripts, screenshots, recordings and signing files stay in private local handoff and diagnostic files. Resume from the local HANDOFF.md for actual deployment state and remaining verification.

## Windows Build Findings

Native Windows tests exposed a drive-path URI error in the SQLite WAL reader. The corrected absolute file URI passed on ARM64. Speech packaging then exposed an upstream compiler restriction: MSVC cannot build its portable ARM target with native tuning disabled. The build uses ClangCL and an ARMv8-A baseline. A later workflow gate exercises the actual installer, login task and downloaded model warmup before uploading the Windows package. The platform split keeps Claude's existing SIGTERM behavior on Mac and uses native process-tree termination on Windows.

The verified Android UI shipped in version 0.1.5. The following 0.1.6 package includes the platform adapter correction and the Windows runtime once its gates pass. Production upgrades use the same Android signing identity and retain data.
